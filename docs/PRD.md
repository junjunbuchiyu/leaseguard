## 1. 项目概述

### 1.1 背景

2025-09-15《住房租赁条例》（国务院令第 812 号）施行，首次以行政法规形式规定押金返还、非居住空间不得单独出租、转租资金监管、禁止暴力驱赶等事项。但大学生首次租房时，拿到的仍是一份由房东/中介提供的、条款倾斜的合同，**看不懂、不敢问、不知道哪条能谈**。

### 1.2 一句话定位

> 上传或拍一张租房合同，60 秒告诉你哪几条会坑你、依据哪条法、以及怎么跟房东谈。

### 1.3 目标（可衡量）

| 编号 | 目标 | 指标 |
|---|---|---|
| G1 | 风险识别有效 | 5 份样张合同，每份命中预埋坑 ≥3 个，误报 ≤1 条 |
| G2 | 结论可溯源 | 风险条目法条引用率 100%，点击可定位原文 |
| G3 | 隐私可控 | 身份证/手机号/银行卡在出端前 100% 脱敏（抓包验证） |
| G4 | 体验达标 | 10 页合同端到端 ≤60s（P95），流式首字 ≤3s |
| G5 | 评分覆盖 | 评分表 6 个 AI 子项均有可见证据（见 §13） |

### 1.4 非目标（明确不做）

- 不做法律咨询/代理，不出具"合同无效/违法"的确定性法律结论
- 不做律师撮合、不做付费咨询
- 不做合同起草（只做审查 + 改写建议）
- 不做多语言

## 2. 用户与场景

### 2.1 用户画像

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| **P1 首次租房的大学生**（主） | 大四/研一，第一次签租房合同，预算有限，怕押金被扣 | "这份合同有没有坑？哪些能谈？" |
| **P2 换房租客**（次） | 有过一次租房经历，被扣过押金 | "押金条款、维修责任写得清不清楚" |
| **P3 家长/朋友**（辅助） | 帮孩子看合同 | "一眼看懂风险等级" |

### 2.2 核心场景（用户故事）

- **US-1**：我在中介店里，房东把合同拍照发我，我想 1 分钟内知道能不能签。
- **US-2**：合同写"押金退还需扣除房屋折旧费"，我不知道这合不合理，想看到依据。
- **US-3**：我知道某条不合理，但不知道怎么开口，想要一段能直接发给房东的话。
- **US-4**：我改完条款想再核一遍，看风险有没有降下来。

### 2.3 关键旅程

```
进入首页 → 上传/拍照 → (解析校正) → 自动脱敏 → 审查中(Agent 步骤可见)
   → 风险工作台(原文高亮 + 风险卡 + 法条) → 生成谈判话术 → 导出体检报告
```

## 3. 术语

| 术语 | 定义 |
|---|---|
| 条款（Clause） | 合同中可独立审查的最小单元，通常以"第X条"或编号分隔 |
| 风险项（RiskItem） | 一条条款 + 一个风险判定 + 法条依据 + 建议 |
| 体检分（Score） | 0–100，按风险项加权扣分后的总分 |
| 法条锚点（LawRef） | 法条 id + 原文片段 + 命中理由，可点击溯源 |
| Agent 步骤 | 审查管线中的一个可观测阶段（解析/切分/检索/判定/建议） |

## 4. 范围与优先级

| 优先级 | 含义 | 内容 |
|---|---|---|
| **P0** | 必须有，缺了不能提交 | 上传解析、脱敏、条款切分、风险审查、法条引用、风险工作台、报告导出、免责 |
| **P1** | 应该有，决定拿奖 | Agent 步骤可视化、谈判话术、MCP Server、语音播报、在线部署、法规库页 |
| **P2** | 有余力再做 | 改后复查 diff、多合同对比、历史记录、地方规定差异化、语音提问 |

**单人排期原则**：P0 全绿才碰 P1；P2 一律不做。

## 5. 功能需求

> 格式：编号 / 描述 / 优先级 / 验收标准

### FR-01 合同上传与解析（P0）

- 三种入口：**PDF**、**图片（JPG/PNG，多页）**、**粘贴文本**
- **图片路径（主）**：`deepseek-flash` 图像理解 → 直接输出结构化 Markdown 合同文本（保留条款编号与换行）
  - 单请求可传多张（≤600 张，单图 ≤32MiB），10 页合同一次传完
  - 要求模型"逐字转写，不纠错、不总结、不补全缺失内容"，缺失处输出 `【原件此处模糊】`
- **PDF 路径**：先取文本层（`pdfjs-dist`）；文本层为空（扫描件）则按页转图走视觉
- **兜底**：视觉调用失败 → 端侧 `tesseract.js`（chi_sim）OCR → 仍失败则手动粘贴
- 解析结果进入**可编辑文本框**，用户可校正
- 验收：
  - [ ] 3 类入口均可产出纯文本
  - [ ] 10 页图片合同一次解析成功，条款编号保留
  - [ ] 模糊件有显式标记，不静默编造
  - [ ] 识别结果可编辑、可重解析

### FR-02 PII 脱敏（P0）

- 出端前本地替换：身份证号、手机号、银行卡号、详细门牌号、姓名（可选）
- 占位符形如 `【身份证1】`，映射表仅存内存，不落库
- UI 明示："已本地遮盖 N 处敏感信息"
- 报告导出可选"还原真实信息"（默认不还原）
- 验收：
  - [ ] 抓包确认请求体中无原始 PII
  - [ ] 脱敏前后对比可展示
  - [ ] 映射表随会话销毁

> 注意：图片路径下 PII 以图像形式存在。**默认先视觉转写 → 文本脱敏 → 再进入后续 LLM 调用**；原始图片不进入检索/判定环节，且不持久化。

### FR-03 条款切分（P0）

- 规则优先：`第[一二三四五六七八九十百]+条` → `^\d+[.、]` → 空行分段三级策略
- 保留原文偏移量（`start/end`），供高亮定位
- 切分失败 → 按语义段落分块（≤500 字/块），标记"未能识别条款结构"
- 验收：
  - [ ] 样张切分准确率 ≥90%
  - [ ] 每个条款有唯一 id 与偏移

### FR-04 条款分类（P0）

- 枚举：`押金 / 租金与费用 / 维修责任 / 提前解约 / 转租与续租 / 房屋状况与设施 / 隐私与入户 / 备案与证件 / 违约与赔偿 / 其他`
- 规则关键词 + LLM 批量分类（每批 ≤6 条，关闭思考模式）
- 验收：样张分类准确率 ≥85%，错误不阻断风险审查

### FR-05 风险审查（P0，核心）

- 每条条款输出：风险等级（高/中/低/正常）、问题描述（一句话）、置信度（0–1）
- 判定口径（写进系统提示，禁止自由发挥）：
  - **高**：违反《住房租赁条例》《民法典》强制性/禁止性规定，或显著加重承租人责任（押金无理由不退、可随时清退、维修全归租客、放弃诉讼权利）
  - **中**：约定不明或明显不对等（押金扣减情形未列举、维修无响应时限、违约金过高）
  - **低**：表述模糊但影响有限（"合理使用""适当补偿"）
  - **正常**：符合示范文本或无明显偏斜
- 验收：
  - [ ] 5 份样张，每份高风险命中 ≥1、预埋坑命中 ≥3、误报 ≤1
  - [ ] 每条风险有等级、置信度、原文定位

### FR-06 法条检索与引用（P0，RAG）

- 本地法规库（§7.1），混合检索：BM25 + 向量余弦，合并重排取 Top-5
- **约束**：LLM 只能从检索到的候选法条中选择，不得生成法条内容
- 每条风险挂 1–3 个 `LawRef`：id、条号、原文片段、命中理由
- UI 可点开法条全文并高亮命中句
- 验收：
  - [ ] 引用 100% 来自本地库（校验 id 存在）
  - [ ] 每条引用可定位原文
  - [ ] 人工抽查 20 条，0 编造条号

### FR-07 修改建议与谈判话术（P0/P1）

- 高危/中危条款给出：**建议改法**（可直接替换的条款文本）+ **谈判话术**（可直接发微信）
- 话术风格：不对抗、给依据、给台阶
- 验收：话术可复制、含法条依据、50–150 字

### FR-08 风险工作台（P0，主界面）

- 三栏：左＝原文（条款卡 + 风险色条）、中＝风险清单（排序/筛选）、右＝详情（问题/法条/建议/话术）
- 顶部：体检分 + 风险统计 + 审查进度
- 交互：点风险 → 左栏滚动定位高亮；点条款 → 右栏展示
- 移动端（≤768px）：Tab 切换「原文 / 风险 / 建议」
- 验收：375/768/1440 三档可用，无横向滚动

### FR-09 Agent 步骤可视化（P1，评分关键）

- 管线展示：解析 → 脱敏 → 切分 → 分类 → 检索 → 判定 → 建议
- 每步：状态、耗时、关键产出（"检索到 8 条候选法条"）
- 工具调用可见：工具名 + 入参摘要 + 返回条数
- 验收：审查中步骤实时推进；失败步骤有原因

### FR-10 报告生成与导出（P0）

- 内容：合同摘要（租金/押金/租期/双方）、体检分、风险分布、风险明细（含法条）、修改建议汇总、免责声明
- 导出：浏览器打印为 PDF（`@media print` 专用样式），零额外依赖
- 验收：导出 ≤6 页，排版不错位，含免责声明

### FR-11 免责与合规提示（P0）

- 首访弹窗 + 报告页固定文案：
  > 本工具基于公开法规对合同文本做风险提示，不构成法律意见；重大权益事项请咨询执业律师或当地住建部门。
- 措辞约束：禁止"该条款无效/违法"，改为"可能被认定为…，建议核实/协商修改"
- 验收：全局文案统一；绝对化结论被后处理替换

### FR-12 法规库浏览页（P1，加分）

- 法规列表（名称/层级/施行日期/条数）、标签筛选、关键词搜索
- 价值：让评委直观看到 RAG 语料真实、结构化
- 验收：3 部法规、116 条，可搜索、可按标签筛选

### FR-13 MCP Server（P1，4 分）

- 独立进程 `mcp/server.ts`，stdio 传输，暴露 3 工具：
  - `search_law(query, tags?, topK?)`
  - `calc_penalty(monthlyRent, months, rate)`
  - `redact_pii(text)`
- 应用内通过 MCP 客户端调用（与内部函数复用同一实现）
- 验收：`npx @modelcontextprotocol/inspector` 能列出并成功调用 3 工具

### FR-14 语音播报 / 语音提问（P1，多模态）

- 播报：`speechSynthesis` 朗读风险摘要（Edge/Chrome 中文语音）
- 提问：`SpeechRecognition`（zh-CN）语音输入；**特性检测不可用则隐藏入口**，不报错
- 验收：播报可中断/重播；语音输入失败回落文本

### 6.1 模型与调用矩阵

| 阶段 | 模型 | 思考模式 | 输出 |
|---|---|---|---|
| 图像/PDF → 文本转写 | `deepseek-flash`（视觉） | disabled | Markdown 文本 |
| 条款分类 | `deepseek-flash` | disabled | JSON 数组 |
| 风险判定（常规） | `deepseek-flash` | disabled | JSON |
| 风险判定（高危复核） | `deepseek-v4-pro` | enabled（effort=low） | JSON |
| 建议改法 / 谈判话术 | `deepseek-flash` | disabled | JSON |

**关键 API 事实（实现前必读）**

| 事项 | 说明 |
|---|---|
| 模型名 | `deepseek-flash`（主力）、`deepseek-v4-pro`（终判）；旧名 `deepseek-v4-flash` 仍可调用但会路由到新模型 |
| 视觉 | 仅 `deepseek-flash` 支持；JPEG/PNG/GIF/WebP；图片**只能放在 user 消息**；单图 ≤32MiB；单请求 ≤600 张 |
| 图片 token | 每张图自动缩放，**上限 1024 tokens**（与分辨率无关）；一张 A4 拍照 ≈1k tokens |
| 上下文 | 1M，10 页合同整篇可一次喂入，无需强分块 |
| 思考模式 | **默认开启**；开启时不支持 `temperature`；关闭用 `{"thinking":{"type":"disabled"}}` |
| 思考 + 工具 | 携带 `tools` 的请求，历史轮次必须回传 `reasoning_content`，否则 400 |
| JSON | 支持 `response_format: json_object`；提示词中必须出现 "json" |
| 成本 | flash：输入 1–2 元/M、输出 4–8 元/M（空闲/高峰）。单份合同 ≈25k tokens ≈ **¥0.05 以内** |

### 6.2 审查管线（AI-02 的实现定义）

```
① parse    视觉/PDF → 合同文本（Markdown，保留条款编号）      [flash·视觉]
② redact   本地正则 → redactedText                          [tool: redact_pii]
③ split    规则切分（带偏移）                                 [本地]
④ classify 批量分类 → tag[]                                  [flash·JSON]
⑤ retrieve 混合检索：每条款 Top-5 候选法条                     [tool: search_law]
⑥ judge    等级 + 问题 + 从候选选依据 + 置信度                 [flash / pro]
⑦ advise   建议改法 + 谈判话术（仅高/中危）                    [flash·JSON]
⑧ score    加权汇总 + 报告组装                                [本地 + export_report]
```

**失败降级**

| 失败点 | 处理 |
|---|---|
| 视觉转写失败/超时 | 重试 1 次 → 端侧 OCR → 手动粘贴 |
| 分类 JSON 非法 | 关闭思考 + temperature 0 + 重试 1 次 → 标"未分类" |
| 检索无候选 | 该条只给"建议核对"，不给法条（**宁缺勿编**） |
| 判定超时 | 该条标记"待人工复核"，不阻塞整体 |

## 7. 数据需求

### 7.1 法规库（RAG 语料）

| 来源 | 范围 | 条数 |
|---|---|---|
| 《民法典》 | 第 703–734 条（租赁合同章）+ 第 509 / 563 / 577 / 584 / 585 / 590 条（合同通则） | 38 |
| 《住房租赁条例》（国令 812 号，2025-09-15 施行） | 全文 | 50 |
| 《商品房屋租赁管理办法》（住建部令第 6 号） | 全文 | 28 |
| **合计** | | **116** |

> **取舍说明**：首版不收录地方性租赁条例与合同示范文本。地方规定多制定于《住房租赁条例》之前，部分条文已被上位法覆盖，混入检索会出现"引用已冲突/失效条款"，比少几条更致命。宁可少而准：每条都能点回官方原文。

```ts
interface LawArticle {
  id: string            // "住房租赁条例#10"
  law: string
  level: '法律' | '行政法规' | '部门规章' | '地方规定' | '示范文本'
  article: string       // 第十条
  text: string          // 原文，逐字不改写
  tags: ClauseTag[]
  effectiveDate: string // 2025-09-15
  sourceUrl: string     // gov.cn 原文链接
}
```

要求：**逐字原文、可溯源、带 tags**（tags 用于检索加权与 UI 筛选）。

### 7.2 合同样本（测试与演示）

| 编号 | 类型 | 预埋问题 |
|---|---|---|
| C1 | 中介标准版 | 押金扣减情形未列举、维修 7 日无响应 |
| C2 | 房东自拟版 | 可随时进入房屋、"折旧费"抵扣押金、提前解约扣 2 个月租金 |

### 7.3 数据存储

- MVP **不落库**：会话内存 + `sessionStorage`
- 法规库：构建期生成 `data/laws.jsonl` + `data/embeddings.json`，启动加载进内存索引
- 原始合同图片/文本不持久化，会话结束即释放

├─ components/

### 10.3 核心接口

```ts
// POST /api/audit/parse  (multipart: file | text)
→ { docId, text, pages, source:'vision'|'pdf-text'|'ocr'|'paste', warnings[] }

// POST /api/audit/stream  (SSE，AI SDK 自定义 data part)
body: { docId }
events:
  { type:'step',   step:'retrieve', status:'done', ms:820, detail:'命中 8 条候选' }
  { type:'clause', clause: Clause }
  { type:'risk',   risk: RiskItem }
  { type:'score',  score: { total: 62, high: 3, medium: 2, low: 1 } }
  { type:'done',   reportId: string }

// GET /api/law/search?q=&tags=&topK=
→ { items: (LawArticle & { score:number, snippet:string })[] }
```

### 10.4 核心数据结构

```ts
type RiskLevel = 'high' | 'medium' | 'low' | 'ok'

interface Clause {
  id: string; no: string; text: string
  start: number; end: number
  tag: ClauseTag; confidence: number
}

interface RiskItem {
  id: string; clauseId: string
  level: RiskLevel; title: string; issue: string
  confidence: number
  basis: LawRef[]
  suggestion: string
  revisedClause?: string
  negotiation?: string
}

interface LawRef {
  lawId: string; law: string; article: string
  quote: string; reason: string
}

interface AuditReport {
  id: string; createdAt: string
  contract: { city?: string; rent?: number; deposit?: number; term?: string }
  score: number; summary: string
  risks: RiskItem[]; stats: Record<RiskLevel, number>
  disclaimer: string
}
```

### 10.5 提示词规范（三条硬约束）

1. 只允许引用 `candidates` 中的法条，禁止生成新条号或改写原文
2. 不得给出"合同无效/条款违法"的确定性结论，只能给"可能被认定为…"的风险提示
3. 输出必须匹配 JSON schema；缺失字段填 `null`，不得编造

### 10.6 实现陷阱（提前避坑）

- 思考模式默认开启且**不支持 temperature**：抽取/分类必须显式关闭，否则输出不稳定、延迟翻倍
- 携带 `tools` 时，历史轮次必须回传 `reasoning_content`，否则 400
- 图片只能放 `user` 消息；`system`/`assistant` 带图直接 400
- 多张图片请求体积受 48MiB 限制，大图先压缩到长边 ≤2000px
